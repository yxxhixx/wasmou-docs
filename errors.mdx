---
title: Errors
description: Status codes, messages and what to do about them.
---

Errors keep the standard envelope:

```json
{ "status": "error", "message": "Insufficient balance.", "data": null }
```

| HTTP | When | What to do |
| --- | --- | --- |
| `400` | The request was understood but could not be completed: not enough balance, out of stock, invalid input. `message` says why. | Fix the cause. Do not retry unchanged. |
| `401` | Missing or invalid `X-Api-Key`, or API access is not enabled for your account. | Check the key. It may have been rotated. |
| `403` | The request came from an IP address that is not on your allow-list. | Add the IP in the app, or remove the restriction. |
| `404` | Unknown order, product or route. | Check the ID. |
| `422` | Validation failed. `data` lists the fields. | Correct the fields. |
| `429` | More than 60 requests per minute. | Wait until the reset time in `data.reset`. |
| `500` / `502` | Something went wrong on our side or upstream. | Retry reads after a few seconds. For purchases, check `GET /orders` first. |

## Common messages

| Message | Meaning |
| --- | --- |
| `Insufficient balance.` | Available balance is lower than the order total. |
| `Insufficient allocated stock. Only N unit(s) remaining…` | Your allocation for this product is too small. Nothing was charged. |
| `Your allocated stock for this product is not currently available.` | Your allocation is paused or expired. |
| `IP address not allowed` | See `403` above. |
| `API key is required` | The `X-Api-Key` header is missing. |
